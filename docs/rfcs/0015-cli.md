## 1. Summary

Rewrite `@genoacms/cli` on top of `@genoacms/config`:

- **Dev and builds:** no `npm explore` and no `GENOA_BUILD`. The CLI finds the installed core, spawns core's own Vite with `cwd` = core, and passes the D7 environment (`GENOA_PROJECT`, `GENOA_CONFIG`, `GENOA_TARGET`, `GENOA_MODE`).
- **`build`:** loads the config, chooses the target, runs Vite, then writes the artifact's runtime `package.json`.
- **`deploy`:** builds, resolves the target's options through a host (so `secret()` works through the configured store), and runs the target's procedure.
- **`database` and `roles`:** run on a host or on the manifest.
- **`rotate-root`:** runs core's script through Vite's server API instead of `npm explore … npm run`.
- **`init`:** scaffolds `genoa.config/` (U12): `development.ts`, `production.ts`, and the shared `collections.ts`, `authorization.ts`, `security.ts` and `languages.ts` both import.

Every command accepts `--config` (optional, U9) and `--mode`.

## 4. Specification

### 4.1 `src/args.js`

```js
/**
 * @param {string[]} argv process.argv.slice(2)
 * @returns {{ command?: string, target?: string, config?: string, mode?: 'development'|'production', noInline: boolean }}
 */
function parseCliArgs (argv)
```

It uses `node:util` `parseArgs` with:

```js
{ options: { config: { type: 'string' }, mode: { type: 'string' }, 'no-inline': { type: 'boolean', default: false } }, allowPositionals: true, strict: true }
```

- `positionals[0]` is `command`, and `positionals[1]` is `target` (`build` and `deploy` only).
- `run` is normalized to `dev`.
- `--mode` must be `development` or `production`; otherwise it throws `cli/invalid-mode`.
- An unknown flag throws. `parseArgs` in strict mode does this already.

**Default modes**, applied in `index.js` when `--mode` is absent:

| Command | Default mode |
| :-- | :-- |
| `dev` | `development` |
| `build`, `deploy` | `production` |
| `database`, `roles`, `rotate-root` | `development` |

### 4.2 `src/project.js`

```js
/**
 * @returns {{ root: string, file?: string, coreDir: string }}
 */
function resolveProject ({ cwd, config })
```

- `root = cwd`, and `file = config === undefined ? undefined : resolve(cwd, config)`.
- `coreDir`:
  - if `<root>/package.json` has `name === '@genoacms/core'`, it is `root`. That is the monorepo, where core is the project, and core cannot self-reference by name because it has no `exports` field.
  - otherwise, `dirname(resolveFromProject('@genoacms/core/package.json', root))`. A failure throws `cli/core-not-installed: install @genoacms/core in <root>`.

### 4.3 `src/environment.js`

`genoaEnvironment({ root, file, target, mode })` returns an object containing `GENOA_PROJECT: root`
and `GENOA_MODE: mode`, plus `GENOA_CONFIG` and `GENOA_TARGET` only when they are defined. It sets no
other keys.

### 4.4 `src/vite.js`

- `spawnVite(coreDir, args, env)`:
  1. Resolve Vite's CLI as `join(dirname(resolveFromProject('vite/package.json', coreDir)), <pkg.bin.vite>)`.
  2. `spawn(process.execPath, [viteBin, ...args], { cwd: coreDir, env: { ...process.env, ...env }, stdio: 'inherit' })`.
  3. Resolve on exit code 0; otherwise reject with `cli/vite-failed: vite <args> exited with <code>`.

  Never call core's npm scripts (R8).
- `runCoreScript(coreDir, script, env)`:
  1. Assign `env` onto `process.env`.
  2. Import Vite from `resolveFromProject('vite', coreDir)`.
  3. `createServer({ root: coreDir, configFile: join(coreDir, 'vite.config.ts'), server: { middlewareMode: true, hmr: false }, appType: 'custom', logLevel: 'error' })`.
  4. `await server.ssrLoadModule(join(coreDir, script))`, then `await server.close()` in `finally`.

  This is what `vite-node` did, without depending on it. `vite-node` is a devDependency of core, so it is absent from user installs.

### 4.5 `src/dev.js`

`dev({ root, file, coreDir, mode })` calls
`spawnVite(coreDir, ['dev', '--host'], genoaEnvironment({ root, file, mode }))`. `--host` keeps parity
with core's `dev` script, which `genoa run` used through `npm explore`.

### 4.6 `src/build.js`

```js
/**
 * @returns {Promise<{ manifest: import('@genoacms/config').Manifest, target: string, buildDir: string }>}
 */
async function build ({ root, file, coreDir, target, mode, noInline }) {
  const manifest = await loadConfig({ root, file, mode, forbidInline: noInline })
  const chosen = chooseTarget(manifest, target)
  await spawnVite(coreDir, ['build'], genoaEnvironment({ root, file, target: chosen, mode }))
  const buildDir = join(root, '.genoacms', 'build')
  const { blind } = await createRuntimePackage({ buildDir, coreDir, root, manifest })
  reportBlindImports(blind)
  return { manifest, target: chosen, buildDir }
}
```

- `chooseTarget(manifest, target)`: `target ?? deployment.default ?? first key`. With no targets it throws `config/no-deployment-target`, and an unknown name throws `config/unknown-target` listing the known ones.
- `reportBlindImports(blind)`: one `log.warn` per entry, after the line `These imports are invisible to the dependency scan; confirm each resolves at runtime:`.

### 4.7 `src/deploy.js`

```js
async function deploy (ctx) {
  const built = await build(ctx)
  const entry = built.manifest.config.deployment.targets[built.target]
  const descriptor = (await importFromProject(entry.adapter, ctx.root)).default
  const host = createHost({ manifest: built.manifest, load: s => importFromProject(s, ctx.root), projectRoot: ctx.root })
  try {
    const options = await host.resolve(entry.options, descriptor.secretOptions ?? {}, `deployment.targets.${built.target}.options`)
    const workDir = await freshDirectory(join(ctx.root, '.genoacms', 'deploy', built.target))
    const procedure = (await descriptor.procedure()).default
    await procedure(options, { projectRoot: ctx.root, buildDir: built.buildDir, workDir, target: built.target })
  } finally {
    await host.close()
  }
}
```

`freshDirectory(path)`: `rm(path, { recursive: true, force: true })` then `mkdir(path, { recursive: true })`.
The path is always under `<root>/.genoacms/deploy/`.

Spinners: keep the `@clack/prompts` spinners with today's three phases ("Building CMS code",
"Resolving deployment options", "Deploying code"). Drop "Building config".

### 4.10 `src/init.js` and `src/templates/`

`init` scaffolds the whole `genoa.config/` directory (U12, architecture §10 P1). The development and
production configs import the same shared modules, so roles, security seeds, collections and languages
have one definition from the start. A later copy of `development.ts` into `production.ts` would otherwise
duplicate the authorization stanza, and the two copies could drift apart unnoticed.

`init` keeps its prompts (package manager, adapter suite, authentication adapter). What it installs:
- `@genoacms/core`, `@genoacms/config`, `@genoacms/contracts`, `@genoacms/adapter-secrets-env`, `@genoacms/adapter-node`, `@genoacms/language-adapter-ts`;
- the chosen suite;
- the chosen authentication adapter.

`@genoacms/config` and `@genoacms/contracts` are direct dependencies, because the scaffolded files
import them: the config helpers, and the collection types and schema helpers (strict pnpm).

**Templates**, under `src/templates/`. They are read as text and never imported. Each placeholder is a
`%name%` token inside a string literal, so every template is also valid TypeScript:

| Template | Written to | Content |
| :-- | :-- | :-- |
| `development.ts` | `genoa.config/development.ts` | See below. |
| `production.ts` | `genoa.config/production.ts` | See below. |
| `collections.ts` | `genoa.config/collections.ts` | `export const collections: CollectionReference[] = []`, typed from `@genoacms/contracts/database`. Above it, a doc comment explains that a collection describes data that already exists in the project's database, so GenoaCMS can edit it in place (the name, see the introduction page). Below the array, a commented-out example collection: `name`, `primaryKey`, and a `schema` with a uuid `id`, a string `name` and a `storageResource` image, imported from `@genoacms/contracts/schemas`. |
| `authorization.ts` | `genoa.config/authorization.ts` | `export const authorization: AuthorizationConfig`: the `authorization` stanza of today's `src/genoa.config.js`, with its comments verbatim. |
| `security.ts` | `genoa.config/security.ts` | `export const security: SecurityConfig`: the `security` stanza of today's `src/genoa.config.js`, with its comments verbatim. |
| `languages.ts` | `genoa.config/languages.ts` | `export const languages`: core's `genoa.config/languages.ts` verbatim, which is the `typescript` provider on `@genoacms/language-adapter-ts` with `target: 'es2020'`, and its comments. The loader requires the `languages` stanza (RFC-0003 rule 1, `config/missing-stanza`). |

`development.ts`:
- the §4.1 structure of RFC-0014, with the shared modules imported from `./collections.js`, `./authorization.js`, `./security.js` and `./languages.js`, but:
  - `authentication` uses `%authentication%` with `credentials: secret('GENOACMS_ADMIN_CREDENTIALS')`;
  - the storage provider is keyed `storage` and uses `%storage%`, and the database provider is keyed `database` and uses `%database%`. Both have options `{}` and a `// TODO: options, see the adapter's README` comment;
  - `buckets: { 'your-bucket': { provider: 'storage' } }` and `defaultBucket: 'your-bucket'`, with a `// TODO: the name of a bucket your project already uses` comment;
  - `databases: { database: { provider: 'database', collections } }`;
  - `secrets` uses `@genoacms/adapter-secrets-env`, with RFC-0014's "Development only" comment;
  - `deployment.targets.local` uses `@genoacms/adapter-node`;
- a comment explaining how to put `GENOACMS_ADMIN_CREDENTIALS` (single-line JSON) into `.genoacms/secrets.env`.

`production.ts`:
- the same `authentication`, `storage`, `database` and shared imports as `development.ts`. The storage and database options comment reads `// TODO: options; omit credentials to use the platform's default credentials`;
- `secrets: { providers: { secrets: secretsProvider('%secrets%', {}) } }`, with a comment that the production store must hold `GENOACMS_ADMIN_CREDENTIALS`;
- `deployment: { targets: { '%target%': deploymentTarget('%deployment%', {}) } }`, with a `// TODO: options, see the adapter's README` comment.

Every template also carries one `import type {} from '<specifier>'` line per adapter it names, for the
registry augmentation (RFC-0003). The specifier in these lines is the same placeholder.

**Suite mapping.** `renderTemplate(template, values)` replaces every `%name%` token. It is a pure
function, exported for tests. `initTemplateValues(suite, authentication)` builds `values`:

| Placeholder | `gcp` | `aws` | no suite |
| :-- | :-- | :-- | :-- |
| `%storage%` | `@genoacms/adapter-gcp/storage` | `@genoacms/adapter-aws/storage` | `TODO: storage adapter` |
| `%database%` | `@genoacms/adapter-gcp/database` | `@genoacms/adapter-aws/database` | `TODO: database adapter` |
| `%secrets%` | `@genoacms/adapter-gcp/secrets` | `TODO: secrets adapter` (the AWS suite has none) | `TODO: secrets adapter` |
| `%deployment%` | `@genoacms/adapter-gcp/deployment` | `@genoacms/adapter-aws/deployment` | `TODO: deployment adapter` |
| `%target%` | `gcp` | `aws` | `cloud` |

`%authentication%` is `@genoacms/authentication-adapter-array` for `array`, and
`TODO: authentication adapter` otherwise.

A `TODO` specifier cannot be resolved, so the loader rejects the config and names the entry. That
cannot break `genoa dev` because of `production.ts`: the default lookup never loads it (U12).

**Writing.** `prepareConfig(cwd, values)`:
1. Refuses to overwrite. If `<cwd>/genoa.config.ts` exists, or `<cwd>/genoa.config/` contains any of the six target files, it throws `cli/config-exists: <path>` naming the first one found, and writes nothing.
2. Creates `<cwd>/genoa.config/` and writes the six rendered files.
3. Appends `.genoacms/` to `<cwd>/.gitignore`, creating the file if needed and skipping the append if the line is present.

Finally `init` prints:

```
Config written to genoa.config/.
Describe the data your project already has in genoa.config/collections.ts, then run:
  genoa dev
Before deploying, fill in genoa.config/production.ts and run:
  genoa deploy --config genoa.config/production.ts
```

## 5. Tests (`node --test`)

- **`args`:**
  - `['build', 'gcp', '--config', 'x.ts', '--no-inline']` parses to command `build`, target `gcp`, config `x.ts`, `noInline: true`;
  - `['run']` parses to command `dev`;
  - `['build', '--mode', 'staging']` throws `cli/invalid-mode`;
  - an unknown flag throws.
- **`project`:**
  - a temp root whose `package.json` is `@genoacms/core` gives `coreDir === root`;
  - a temp root with `node_modules/@genoacms/core/package.json` gives that directory;
  - a root with neither throws `cli/core-not-installed`;
  - `--config` resolves relative to `cwd`.
- **`environment`:** only defined keys are present, and the values are passed through unchanged.
- **`init`:**
  - for each suite (`gcp`, `aws`, none) and each of the six templates, `renderTemplate(template, initTemplateValues(suite, 'array'))` leaves no `%` token;
  - `gcp`: the rendered `production.ts` contains `@genoacms/adapter-gcp/secrets` and `@genoacms/adapter-gcp/deployment`;
  - `aws`: the rendered `production.ts` contains `TODO: secrets adapter` and `@genoacms/adapter-aws/deployment`;
  - no suite: the rendered `development.ts` contains `TODO: storage adapter` and `TODO: database adapter`;
  - `prepareConfig` in an empty temp directory writes exactly the six files under `genoa.config/` and one `.genoacms/` line in `.gitignore`. A second call throws `cli/config-exists` and leaves every file byte-identical.
- **Existing:** `test/declaration.test.js` is unchanged and passes.

## 8. Critique

**Pros.**
- The pipeline is explicit: one process boundary with named environment facts, no relative directory walks, and no npm-script indirection.
- `deploy` resolves secrets exactly as the runtime would.
- `roles` is offline by construction.

**Cons & trade-offs.**
- `runCoreScript` starts a Vite server in-process to run one script, which is heavier than `vite-node`. It avoids a dependency users do not have.
- Default modes differ by command. That is documented in §4.1, but a surprise for someone who expects one global default.

**Blindspots.**
- `runCoreScript` loads SvelteKit's Vite plugin in middleware mode. If a future Kit version refuses `appType: 'custom'`, `rotate-root` breaks while `dev` and `build` keep working.
- `init` cannot type-check the generated config until the user fills in the options. Until then, the loader's `validate` messages are the only guidance.
- `buckets` and `databases` are written into both `development.ts` and `production.ts`, because the two environments may point at different buckets. When they are the same, the mapping is duplicated. Only `collections`, `authorization`, `security` and `languages` are shared by construction.
- The AWS suite scaffolds a `production.ts` that cannot load until an AWS secrets adapter exists, or the user names a third-party one.
- The CLI has no integration test for `deploy`. Its steps are unit-tested in the adapters (RFC-0007, RFC-0012, RFC-0013) and wired here, and the wiring is exercised only by a real deploy (U10).
